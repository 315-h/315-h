# 缓择星球 · 网页版 设计优化方案

> 设计审查 + 可落地优化方案 · 由 UI Designer 产出
> 审查对象：当前 `huanzexingqiu-web/`（8 个 HTML 页面 + `theme.css` 1811 行设计系统 + 11 个 JS 模块）
> 审查维度：信息架构 · 视觉层次 · 布局结构 · 色彩与字体 · 响应式适配 · 用户体验
> 目标：在**保留现有品牌调性（暖米白 / 珊瑚橙 / 低饱和 / 磨砂玻璃 / 极简治愈）**前提下，解决不一致、层级混乱、维护脆弱与移动端短板，形成可落地规范。

---

## 一、审查范围与方法

- **方法**：逐页走查 HTML 结构 + 通读 `theme.css` 设计令牌与组件定义 + 提取断点分布。所有问题均指向具体文件/行号，避免主观臆断。
- **现技术约束**（不可破坏）：纯静态多页、零构建、原生 CSS 变量双主题、localStorage 数据层、SSE 驱动工作台。任何优化必须兼容此底座。
- **产品定位**（来自项目记忆）：AI 产品经理求职作品集；对外口径为"方案对比工具 / 利弊梳理清单"，规避心理咨询类术语。

## 二、现有设计系统概览（基线）

| 维度 | 现状 | 评价 |
|---|---|---|
| 色彩 Token | `--primary #E98A68` / `--primary-strong #D9774F` / `--primary-btn #C2623E` / `--accent #E0D4F0` / `--pos #D8E4ED` / `--cost #F2D7D5`；浅色 `--bg #FAF6F0` `--card #FFF` `--text #333` `--sub #6B6A65` | 品牌色清晰，但**主色被过度复用**（logo/导航/按钮/标签/星轨/强调文字全部暖橙），削弱"中立克制"的产品哲学 |
| 字体 | 仅 `--font` 一个家族变量；正文 `15px/1.7`、h1 `40px`、h2 `24px`、h3 `18px`、small `12px` | **无字号 / 字重 / 行高 scale token**，数值散落各处 |
| 间距 | 仅 `--gap:24px`、`--pad-x:48px`，其余用魔法数字（10/12/16/20/22/32…） | 未形成 8px 基准栅格体系 |
| 圆角 | `--radius-lg 20 / --radius-md 12 / --radius-sm 8`；按钮却用 `16px`、胶囊用 `999px` | **16px 与胶囊未纳入 token** |
| 阴影 | 仅 `shadow` / `shadow-hover` 两档 | 缺 elevation 梯度（卡片/悬浮/弹窗/抽屉无区分） |
| 组件 | `.card` `.btn`(primary/ghost/demo) `.input` `.tag` `.pill` `.chip` `.modal` 等 | 基础组件齐全，但**无统一 API 命名与状态规范** |
| 响应式 | 断点出现在 `1200 / 1024 / 960 / 768 / 700 / 640` 多处，分散在文件各 section | **断点碎片化、标准不统一** |

## 三、问题诊断（按维度）

### 3.1 信息架构（IA）
1. **导航项 PC / 移动不一致**（高优）
   - 桌面 `nav-links` 6 项：首页 / 决策工作台 / 模板库 / 历史星轨 / 我的底线 / 设置与关于。
   - 移动 `tabbar` 仅 5 项，**缺"设置与关于"**（`index.html:124`、`workspace.html:111`、`history.html:76` 等）。移动端用户无法从底部栏直达设置，只能靠汉堡菜单——而设置含"主题 / 数据清理 / 隐私说明"，属于高频功能，被弱化。
2. **导航硬编码重复 ×6**（高优 · 可维护性）
   - 6 个页面各自复制约 26 行 `navbar` + 8 行 `tabbar` SVG（含 5 段 icon path）。任何品牌/文案改动需同步 6 处，极易出现"改了主页忘设置页"的不一致。
3. **页面间层级与回流模糊**
   - `templates.html` 填写页仅有「← 返回模板库」（`templates.html:49`），`history` 详情是抽屉但缺"回到列表"的明确关闭反馈；工作台"保存"动作与"历史星轨 / 我的底线"未建立显式回流路径。
4. **首页与工作台入口重叠**
   - 首页"开始一次抉择"→工作台；"七大场景矩阵"也→工作台带场景参数；工作台自身又有场景选择。新用户可能困惑"到底从哪开始"。

### 3.2 视觉层次（Visual Hierarchy）
5. **标题层级"有名无实"**
   - `h1=40 / h2=24 / h3=18`，但页面区块标题普遍用 `.sec-title`（实测 `24px`，`theme.css:1262`）而非 `h2`；卡片内标题用 `h3(18px)`。`.sec-title` 与 `h2` 同字号却不同语义，且全局 `h2` 几乎未被使用——层级系统未真正生效。
6. **暖橙主色过度曝光**（与品牌哲学冲突）
   - 产品主张"中立、克制、不替你决定"，但 UI 中暖橙出现在 logo、导航激活态、主按钮、标签圆点（`theme.css:286` `currentColor`）、星轨主线、强调文字。全页暖橙削弱了"中性权衡"的调性。
7. **阴影 / 圆角系统单薄**
   - 仅两档阴影；按钮圆角 16px、胶囊 999px 游离于 token 之外，组件外观"差不多但不统一"。

### 3.3 布局结构（Layout）
8. **内容容器 max-width 各自为政**
   - 全局 `--content-max:1280px`，但设置页 `640/520`（`theme.css:1456/1474`）、弹窗 `400`、ws-steps `400`、cap-cards 跟随 1280。缺"宽容器 / 标准容器 / 窄容器"语义。
9. **中等屏（768–1024）双栏挤压**
   - `mode-card` 在 `768px` 以下才转单列（`theme.css:1762`），意味着平板竖屏（768–1024）仍是 50/50 双栏，左表单 + 右预览在两窄列里都很挤。
10. **空状态依赖"等高拉伸"**
    - `#right-empty` 用 `flex:1 + justify-content:center` 居中，依赖右栏被左栏等高拉伸；若左栏内容短（刚进工作台未选场景），右栏也会奇高，空态过度下沉或留白异常。

### 3.4 色彩与字体（Color & Type）
11. **字阶 / 字重 / 行高无 token**
    - 仅 `--font` 一个变量；正文 15/1.7、小字 12/1.6、卡片 13/1.9 等散落各处，难以保证跨页一致。
12. **辅助文本对比度余量不足**
    - `--sub #6B6A65` on `--bg #FAF6F0` ≈ 4.6:1，仅勉强达 AA；当它用于 `12px` 小字（hint/small）时，小字 4.5:1 是下限，几无余量。深色模式 `--sub #A9A29A` on `#2B2724` ≈ 6:1 反而更安全。
13. **中文混排无字距规范**
    - "7 大场景"等中英混排无 `letter-spacing`；卡片内 12–13px 小字行高 1.6–1.9 在移动端偏松。

### 3.5 响应式（Responsive）
14. **断点碎片化**
    - `@media` 分散在文件各 section，且标准不一：全局 `1200/768`，history `960`（`theme.css:1094`）、settings `960`（`1473`）、部分 `700/640`。维护者无法一眼看清响应式全貌。
15. **平板（768–1024）导航悬空**
    - `nav-links` 抽屉化只在 `≤768` 触发（`theme.css:438`）；768–1024 仍是横向 6 项 + logo + 主题/菜单按钮，小平板（如 800px）可能拥挤换行，又无底部栏兜底。

### 3.6 用户体验（UX）
16. **空 / 加载 / 错误态不统一**
    - workspace `ws-empty`、history 空态（`insights-empty`，`theme.css:1044`）、templates、cleanup 各自写法，缺统一 EmptyState 组件。
17. **演示数据入口分散**
    - settings「载入示例数据」+ history 空态 + `_seed_demo.html` 深链，三处入口文案/行为略不同，增加心智负担。
18. **首次访问无引导（onboarding）**
    - 进入首页直接给 KV + 三大能力，缺少"3 步完成一次决策"的轻量引导，新用户不知从首页还是工作台进。

## 四、优化策略（对应问题）

| 问题 | 优化策略 | 改动规模 |
|---|---|---|
| 1 导航不一致 | 移动 tabbar 补齐"设置与关于"为 6 项；或重新定义移动端主导航 = 5 个高频项 + 设置并入抽屉。建议：**tabbar 6 项对齐桌面**（设置用齿轮图标） | 中 |
| 2 导航重复 | **抽离导航为 JS 注入组件**（`ui.js` 渲染 `renderNav(current)` + `renderTabbar(current)`），6 页面统一调用，删除硬编码 | 中（推荐） |
| 3 层级回流 | 统一"页面主标题 h1 + 区块标题用 `.sec-title` 但**纳入 token 并明确语义**"；history 抽屉加"返回列表"关闭按钮可见反馈；工作台保存后显式引导至历史/底线 | 小 |
| 5 层级失效 | 建立 `h1(40) → section-title(28) → card-title(18) → body(15) → sub(13) → micro(12)` 六级字阶，**全部 token 化** | 中 |
| 6 暖橙过度 | 引入**"强调色降级"原则**：导航激活 / 星轨主线 / 标签圆点改用低饱和 `--accent`（淡紫）或中性灰；暖橙仅保留给"主行动按钮 + 关键决策节点"，提升稀缺感 | 小（CSS 变量调整） |
| 7 阴影/圆角 | 增 3–4 档 elevation token（`--elevation-1/2/3`）；圆角补 `--radius-pill:999px`、`--radius-btn:14px` 纳入 token | 小 |
| 8 容器 | 定义 `--container-wide:1280 / --container:960 / --container-narrow:640` 三档语义容器 | 小 |
| 9 中等屏 | 双栏断点从 768 提前至 **960**（平板竖屏即转单列或 40/60），避免挤压 | 小 |
| 10 空态 | `#right-empty` 改为 `min-height: 60vh` 兜底而非纯 `flex:1`，避免极端留白 | 小 |
| 11 字体 token | 建 `--fs-*` / `--fw-*` / `--lh-*` 全套 scale | 中 |
| 12 对比度 | `--sub` 由 `#6B6A65` 加深至 `#5C5B56`（≈5.2:1），小字更稳 | 小 |
| 14 断点 | **统一断点为 1280 / 960 / 640 三档**，全局集中管理，删除 700/1024/1200 杂项（保留 768 仅作"双栏→单栏"语义断点，与 960 合并说明） | 中 |
| 15 平板导航 | 在 768–960 区间保留顶部横向 nav，但 `nav-link` 间距收紧、字号 13px；≥960 才允许 6 项宽松排列 | 小 |
| 16 状态统一 | 抽象 `.empty-state` / `.loading` / `.error-state` 通用组件（图标 + 文案 + 可选 CTA） | 中 |
| 17 入口收敛 | 演示数据入口统一为**单一入口**（建议 settings 为主、history 空态复用同一函数），文案统一 | 小 |
| 18 onboarding | 首页 KV 下方加"①选场景 ②填需求 ③看对比 ④预演代价"的 4 步微导览条（可复用 workspace 四步卡片语言） | 小 |

## 五、优化后信息架构与页面结构

### 5.1 全局导航（统一后）
```
顶部固定栏（所有页，≥768）：[Logo]  首页 · 工作台 · 模板库 · 历史 · 底线 · 设置    [主题切换] [菜单]
底部 Tabbar（≤768）：        首页 · 工作台 · 模板库 · 历史 · 底线 · 设置（6 项对齐）
```
- 当前页用 `aria-current="page"` 标记（修复可访问性）。
- 导航由 `ui.js` 统一注入，`data-nav` 标识当前页。

### 5.2 页面结构总览
| 页面 | 角色 | 主区块（优化后） |
|---|---|---|
| `index.html` 首页 | 品牌门面 + 转化入口 | KV（星球+7场景公转）→ 4 步微导览条 → 三大能力 → 七大场景矩阵 → 设计理念 → footer |
| `workspace.html` 工作台 | 核心决策流 | 双栏（≤960 转单栏）：左采集/对话 · 右对比与预演（含现有优化空态） |
| `templates.html` 模板库 | 纯工具 | 模板网格 → 填写表单（两栏，≤768 单栏） |
| `history.html` 历史星轨 | 归档/复盘 | 星轨总览 → 决策洞察 → 筛选+记录流 → 详情抽屉 |
| `bottomline.html` 我的底线 | 个人准则 | 底线列表 + 新增栏 + 引用面板 |
| `settings.html` 设置与关于 | 系统 | 外观 / 数据 / 关于（列表式） |
| `cleanup.html` 数据清理 | 子流程 | 筛选 + 批量清理（由设置进入） |

### 5.3 关键界面模块说明
1. **KV Hero（首页）**：保留中心星球 + 轨道环 + 7 场景卡公转的视觉资产（已是品牌记忆点）。优化：右侧视觉在 ≤960 时下移或简化，避免与左文挤压。
2. **4 步微导览条（新增）**：首页 KV 下用一条横向 `①选场景 ②填需求 ③看对比 ④预演代价` 轻量条，与 workspace 空态语言一致，承担 onboarding。
3. **四步流程卡片（工作台空态）**：即本轮已优化的 `ws-empty`（主角星球 + eyebrow + 标题 + 副标 + 居中四步卡 + 主 CTA + slogan），保持。
4. **统一 EmptyState**：各页空态改为 `.empty-state { icon + title + desc + [cta] }`，历史星轨/模板/清理共用。
5. **详情抽屉（history）**：保留右侧滑出，补"返回列表"可见关闭按钮 + `Esc` 关闭 + focus trap（可访问性）。

## 六、设计规范建议（可落地）

### 6.1 设计令牌（Design Tokens）扩展
```css
:root {
  /* 颜色：保留品牌，新增中性与降级位 */
  --primary: #E98A68;          /* 仅用于主行动按钮 + 关键决策节点 */
  --primary-strong: #D9774F;
  --primary-btn: #C2623E;
  --primary-btn-hover: #A8542F;
  --accent: #E0D4F0;           /* 导航激活 / 星轨主线 / 标签（降级暖橙） */
  --neutral-soft: #EDE7DF;     /* 新增：导航/标签中性底，替代部分暖橙 */
  --pos: #D8E4ED; --cost: #F2D7D5;

  --bg: #FAF6F0; --bg-deep: #F4EDE3; --card: #FFFFFF;
  --text: #333333;
  --sub: #5C5B56;              /* 加深：≈5.2:1，小字更稳 */
  --line: rgba(51,51,51,.08);

  /* 字阶（新增 scale） */
  --fs-display: 40px;  --lh-display: 1.3;
  --fs-section: 28px;  --lh-section: 1.4;   /* 取代散落的 .sec-title 24 */
  --fs-card: 18px;     --lh-card: 1.5;
  --fs-body: 15px;     --lh-body: 1.7;
  --fs-sub: 13px;      --lh-sub: 1.65;
  --fs-micro: 12px;    --lh-micro: 1.6;
  --fw-regular: 400; --fw-medium: 500; --fw-semi: 600;

  /* 间距（8px 栅格） */
  --sp-1:4px; --sp-2:8px; --sp-3:12px; --sp-4:16px;
  --sp-5:24px; --sp-6:32px; --sp-7:48px; --sp-8:64px;

  /* 圆角（补全） */
  --radius-lg:20px; --radius-md:12px; --radius-sm:8px;
  --radius-btn:14px; --radius-pill:999px;

  /* 阴影（elevation 梯度） */
  --elevation-1: 0 2px 8px rgba(51,51,51,.04);
  --elevation-2: 0 12px 40px rgba(233,138,104,.08);   /* 现有 shadow */
  --elevation-3: 0 20px 48px rgba(233,138,104,.16);   /* 现有 shadow-hover */
  --elevation-4: 0 24px 60px rgba(0,0,0,.18);          /* 弹窗/抽屉 */

  /* 容器语义 */
  --container-wide: 1280px; --container: 960px; --container-narrow: 640px;

  /* 统一断点语义（媒体查询引用） */
  --bp-lg: 1280px; --bp-md: 960px; --bp-sm: 640px;
}
```

### 6.2 组件规范（统一 API）
| 组件 | 变体 | 状态 | 规范要点 |
|---|---|---|---|
| Button | `.btn-primary` / `.btn-ghost` / `.btn-demo` / `.btn-danger` | default/hover/active/focus/disabled | 高度 40（移动 44 触控）、圆角 `--radius-btn`、focus 环 `--focus` |
| Card | `.card` | default/hover | 圆角 `--radius-lg`、阴影 `--elevation-2`、hover `--elevation-3` + `-4px` |
| Input | `.input` / `.textarea` | default/focus/error | focus 用 `--primary-strong` 边 + `--focus` 光晕 |
| Tag | `.tag-scene/pos/cost` | — | 圆点用 `--accent/pos/cost` 而非 `currentColor` 暖橙 |
| Modal / Drawer | `.modal-mask/.modal-card` `.detail-mask/.detail-panel` | open/close | 阴影 `--elevation-4`、Esc 关闭、focus trap |
| Nav / Tabbar | `renderNav()` `renderTabbar()` | active | 激活态用 `--accent` 中性底 + `--primary-strong` 文字 |
| EmptyState | `.empty-state` | — | icon + title(`--fs-card`) + desc(`--fs-sub`) + 可选 CTA |

### 6.3 响应式断点（统一为三档）
```
≥1280  宽屏：双栏工作台 50/50，内容 --container-wide
960–1280 标准：双栏转 40/60 或单列（取决于页）
≤960   平板/移动：单栏；顶部 nav 收紧；≤640 显示底部 tabbar（6 项）
```
- 删除散落的 700/1024/1200 杂项，集中到文件末尾"响应式"区段管理。

## 七、实施路线图（优先级）

**P0（一致性 / 可维护性，低成本高收益）**
1. 抽离导航为 `ui.js` 注入组件，6 页统一调用（解决 #2）。
2. 移动 tabbar 补齐"设置与关于"为 6 项，对齐桌面（解决 #1）。
3. 字阶 / 间距 / 圆角 / 阴影 token 化（解决 #5/7/8/11）。
4. `--sub` 加深至 `#5C5B56`（解决 #12）。

**P1（体验与导航）**
5. 首页新增 4 步微导览条（解决 #18）。
6. 统一 EmptyState 组件，历史/模板/清理复用（解决 #16）。
7. 演示数据入口收敛为单一函数（解决 #17）。
8. 双栏断点 768→960（解决 #9/15）。

**P2（打磨）**
9. 暖橙降级原则落地（导航/星轨/标签改 `--accent` 中性）（解决 #6）。
10. 空态 `min-height` 兜底（解决 #10）。
11. 断点统一为 1280/960/640 并集中管理（解决 #14）。
12. 抽屉/模态可访问性（Esc + focus trap + `aria-current`）（解决 #3/UX）。

## 八、落地交付物建议
